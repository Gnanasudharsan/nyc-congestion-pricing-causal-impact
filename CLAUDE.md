# CLAUDE.md — Cordon working agreement (condensed spec)

Re-read this file at the start of every session and every phase.

## Project
- **Cordon** (repo `nyc-congestion-pricing-causal-impact`), by Gnanasudharsan Ashokumar.
- Question: causal effect of NYC congestion pricing (Congestion Relief Zone, Manhattan at/below
  60th St, tolling began **2025-01-05 00:00 America/New_York**) on (1) vehicle traffic and speeds,
  (2) transit ridership, (3) air quality, (4) spillovers to neighborhoods just outside the zone.
- Differentiator: transparently **replicate** headline findings, then **extend** with spillover
  and equity analysis (border neighborhoods, Bronx, upper Manhattan, NJ approaches).
- Bar: a top-tech hiring manager or a policy economist should trust it. Rigor and honesty over
  impressive numbers.
- **Neutral**: contested topic. No advocacy language. Report nulls and unfavorable results.
  Effects always with uncertainty. Give alternative explanations real space.
- **$0 budget**: public data, open-source tools only. Develops on a Mac.

## Stack (locked unless the user agrees)
- Python 3.12 + uv (pinned `uv.lock`). DuckDB + Parquet for storage/aggregation (query TLC
  parquet remotely, select only needed columns). Polars for transforms; pandas where required.
- Causal: statsmodels, linearmodels (TWFE, clustered SEs), pyfixest (heterogeneity-robust DiD,
  wild bootstrap), CausalPy (SC/ITS, Bayesian), pysyncon (classical SC with inference), DoWhy
  (graph + refuters), wildboottest. HonestDiD-style sensitivity: use a maintained Python port if
  one exists, else implement the relative-magnitudes bound and document it in an ADR.
- Viz: matplotlib (paper), Altair/Plotly (site). Write-up: Quarto (HTML site + PDF), GitHub Pages
  via Actions.
- Quality: ruff, mypy (strict), pytest, pre-commit, GitHub Actions CI.
- Reproducibility: `make all` rebuilds from raw downloads. Fixed seeds (`cordon.config.RANDOM_SEED`).
  Data versions (download date, rows, sha256, coverage) in `data/MANIFEST.json`.

## Data rules
- **Every causal design needs a real pre-period.** Record date coverage for every dataset.
  Datasets that begin Jan 2025 (e.g., MTA CRZ Vehicle Entries `t6yz-b64h`) are descriptive
  post-period only — say so.
- Verify every dataset ID, coverage, and column meaning before use. Document in
  `docs/data-catalog.md`.
- Concurrent events are tracked in `docs/confounders.md`; every design states how it handles each.
- `data/raw`, `data/interim`, `data/processed` are gitignored. Commit only small final aggregates
  (< 20 MB total, CI-enforced).

## Git rules
- Commits authored only by the existing git identity (never change `user.name`/`user.email`).
- **No AI attribution anywhere** (no Co-Authored-By, "Generated with Claude Code", Claude-Session)
  in commits, PRs, tags, releases, or code comments. Local `.git/hooks/commit-msg` strips them.
- Conventional commits, small and logical. No secrets. No force-push/history rewrite without
  explicit approval.
- End of each phase: update README status + CHANGELOG, commit
  `chore(release): complete phase N — <name>`, tag `phase-N`, push with tags, show URL.

## How to work
- Each phase: short plan → execute → acceptance checks → commit/tag/push → STOP with
  (a) what was built, (b) findings so far with uncertainty, (c) USER ACTION REQUIRED,
  (d) next phase. Wait for "continue".
- **Pre-registration**: `docs/analysis-plan.md` committed and tagged `analysis-plan-v1` BEFORE any
  treatment-effect estimate. Deviations logged in `docs/deviations.md` with reasons. Exploratory
  analyses labeled exploratory.
- Never tune a design to get significance. If assumptions fail (e.g., pre-trends), report it and
  fall back to a weaker claim.
- Interview-explainable code: clear names, docstrings, no clever one-liners. Notebooks are for
  exploration only, never the source of results. ADR in `docs/adr/` for every methodological choice.
- All numbers in the write-up come from `results/` files generated by code (no hand-typed numbers).

## Layout
```
src/cordon/{ingest,clean,features,designs,robustness,viz}/   config.py  manifest.py
notebooks/ (exploration only)   report/ (Quarto paper + site)   results/ (generated tables)
data/{raw,interim,processed,final}/  data/MANIFEST.json   docs/ (+ docs/adr/)   tests/
```
Make targets: `setup data analysis report all test lint format clean`.

## Phases
0 Foundation + literature · 1 Data audit + pre-analysis plan (tag `analysis-plan-v1`) ·
2 Clean data + descriptives (no effect estimates) · 3 Core causal estimates (estimators unit-tested
on simulated data with known effects) · 4 Spillovers + heterogeneity + equity (ACS; associations,
not causal claims) · 5 Robustness (placebo dates/outcomes/units, leave-one-out donors, DoWhy
refuters, HonestDiD-style bounds; tag each claim robust/fragile/not supported) · 6 Quarto paper +
site (design tokens below; Lighthouse ≥ 90) · 7 Release v1.0.0.

## Design tokens (Phase 6, and all figures)
- Light: ink `#1A2230`, slate `#586274`, paper `#FAFAF8`, surface `#FFFFFF`, line `#DDE1E6`,
  accent `#2F5BD3`. Dark mode required on the site.
- Data: treated/zone `#C8553D`, control `#5B7083`, spillover `#D99A2B`; uncertainty bands at 20%
  opacity of series color. Colorblind-check every figure.
- Type: Source Serif 4 (body), Inter Tight (headings/labels), tabular numerals in tables.
- No gradients, no template filler, direct labels over legends, chart titles state the takeaway.
